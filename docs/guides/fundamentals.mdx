## Components

### Server

The Server, also referred to as the Walker Server, is responsible for handling incoming requests and sending back an Action.

### Client

The Client, also referred to as the Walker Client, is responsible for sending a Map of Items, Flows, and Skills to the server. After receiving an Action from the Server, it match the Action handler to a Flow with the same command to interact with the user application.

## Elements

### Action

Action, a JSON object, is a command sent from the Server to the Client to interact with the user's application.

### Flow

Flow decides what Action type does the Client accepts. Developers have to declare these Flows. Walker provides built-in sets of Flows, which are `none`, `input`, and `click`. There are also specials Flows, such as informative Flows like `success` and `error`, which is not recorded in History.

### Item

Item represents what Walker can interact with, and what Walker see. Before the walk request, the Client with get all DOM elements where id starts with `walker-`.

### Map

Map, a JSON object, is an array of Items sent from the Client to the Server to describe the current landscape of the user application.
